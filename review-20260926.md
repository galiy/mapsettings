# Ревью проекта mapsettings — 2026-09-26

Независимый разбор кода (без внесения изменений). Проверены: `go vet`, `go test`,
`go build` — все три проходят чисто. Ветка `main` (релиз 1.0.0), коммит `efde70f`.

## Резюме

Проект в хорошем состоянии: продуманная структура, чистая абстракция транспортного
слоя за интерфейсом `cellConn`, добротный и защищённый от паник парсер Modbus TCP,
двухуровневая защита опасных ячеек (`danger` + `allowDanger`), маскирование паролей
в логах, верификация записи чтением-обратно. Код последователен, тесты осмысленные.

Главные зоны риска — **безопасность сетевого доступа** (дефолт без авторизации и
привязка на все интерфейсы при том, что API пишет в реальное оборудование) и
**отсутствие сериализации операций записи** при конкурентных запросах. Остальное —
косметика, мёртвый код и мелкие несоответствия.

---

## Критично / Высоко

### 1. По умолчанию сервер открыт на всех интерфейсах без авторизации
- `config.go:62` — `Listen: ":8099"` → `net.Listen` на `0.0.0.0`.
- `main.go:64-65`, `server.go:71-74` — Basic-авторизация отключается, если `-user`/
  `-pass` не заданы (по умолчанию пусто).

В конфигурации по умолчанию **любой хост в сети** может вызывать мутирующие
эндпоинты `/api/apply`, `/api/action`, `/api/time`, т.е. реально писать в EEPROM/RAM
инвертора и выполнять команды (`ComMAP_ON/OFF/Reset` и т.п.). README советует
`http://127.0.0.1:8099/`, но фактически слушается весь интерфейс — расхождение.

Рекомендация: дефолт `127.0.0.1:8099`, либо обязательная авторизация, либо явное
предупреждение в логе при запуске с пустым `-user/-pass` на не-loopback адресе.

### 2. Нет защиты от CSRF / контроля Origin на мутирующих эндпоинтах
`server.go` (`apiApply`, `apiAction`, `apiTime`) не проверяют `Origin`/`Host` и не
используют CSRF-токены. При выключенной авторизации (дефолт) произвольная
веб-страница в браузере пользователя может попытаться отправить запрос на
`http://127.0.0.1:8099/api/action` (класс «localhost-атак»; браузерный Private
Network Access снижает, но не полностью закрывает). Для программы, управляющей
силовым оборудованием, это существенно.

Рекомендация: всегда включать авторизацию, либо валидировать `Origin`/`Host` и
требовать не-simple запрос (JSON уже даёт preflight — но это ненадёжная опора).

### 3. Конкурентные операции записи не сериализуются
Каждый HTTP-запрос открывает собственное соединение и выполняет полную
последовательность `EEPROM WR (0x03) → запись → load_EEProm (0x07)` без
общепроцессного замка. Две вкладки (или два параллельных запроса) дадут
перекрывающиеся сессии записи на одном устройстве — возможны гонки и потеря данных.

Рекомендация: глобальный `sync.Mutex` на операции записи (apply/action/time) в
масштабе приложения, а не только внутри одного соединения.

## Средне

### 4. Пароль Малины хранится открытым текстом
`config.go:30-41` — `connConfig.Password` сериализуется в `mapsettings.json`
(`saveFileConfig`, права `0644`) без шифрования. Также `-pass` виден в `ps`.
Пароль маскируется только в логах (`maskSecret`, `config.go:173`), но не на диске.
Как минимум стоит ужесточить права файла до `0600` и задокументировать риск.

### 5. Мёртвый код — остатки рефакторинга
- `catalog.go:1009-1037` — `mapSettingsTarget`, `validateMapTarget`, метод
  `address()` больше не используются в проде (живы только в `catalog_test.go` и в
  старых worktree из `.kilo/`). `unit` в структуре всегда `1` и нигде не читается
  осмысленно. Кандидат на удаление.
- `web/app.js:292-296` — вложенная функция `vis(...)` внутри `applyCfgVisibility`
  не вызывается.

### 6. Расхождение дефолта протокола записи
`config.go:70` — `defaultConfig().Write.Protocol = "malina"`, но UI
(`app.js:283`, `renderCfgUI`) дефолтит `wrProto` в `"microart"`. При первом запуске
селектор покажет MICROART, тогда как реально сохранённый/действующий конфиг — Малина.
Значение из UI всё равно сохранится при первом изменении, но расхождение вводит в
заблуждение.

### 7. Нет graceful shutdown
`main.go:139` — `select {}` без обработки `SIGINT`/`SIGTERM`; сокеты и файл лога не
закрываются корректно. Плюс `log.Fatalf` в горутине `srv.Serve` (`main.go:129`)
вызывает `os.Exit` без deferred-очистки.

### 8. Непоследовательные коды ответов
Ошибки чтения/подключения отдаются то `400`, то `502` (`server.go`: `apiSettings`
— 502, `apiParam` — 400 для подключения и 502 для чтения, `apiRelays`/`apiApply` —
502). Клиенту это не мешает (он различает по `error`), но семантика плавает.

### 9. Верификация записи игнорирует ошибки чтения-обратно
`catalog.go:1143` — `cells, _ := conn.ReadCells(...)`. Если чтение-обратно не
удалось, верификация молча пропускается (как успех). Также ключ результата
верификации — адрес в hex (`"0x123"`, `catalog.go:1153`), а не исходный `key`
параметра: клиент покажет пользователю малопонятную строку.

### 10. `http.Server` без `WriteTimeout`
`main.go:113-118` — заданы `ReadHeaderTimeout`/`ReadTimeout`/`IdleTimeout`, но нет
`WriteTimeout` (актуально для медленных клиентов на медленных операциях с МАП,
которые идут до 90 с).

## Низко

- `server.go:56` — статические файлы `/static/` отдаются без `Cache-Control`
  (в отличие от index/API, где стоит `no-store`).
- `config.go:113-126` — `configPath()`: если в каталоге бинарника лежит старый
  `mapsettings.json`, он имеет приоритет над текущим каталогом; при `go run` это
  даёт неожиданные результаты.
- `catalog.go:699-721` — `dangerKeys` матчится по `p.Key`, но `normalizeCatalogPairs`
  (`catalog.go:294-296`) может переименовать дублирующиеся ключи добавлением
  суффикса `_%03x`; такая ячейка выпадет из списка опасных. В текущем каталоге,
  видимо, не срабатывает, но хрупко.
- `apiConfig` (POST) сохраняет `req.Listen`/`req.User`/`req.Pass` из текущего
  состояния (`server.go:123-125`), т.е. `listen` из файла невозможно поменять через
  UI, хотя поле существует и `-listen` «переопределяет конфиг» (README).

## Сильные стороны (сохранить)

- Чистая абстракция транспортов (`cellConn` / `cellReader` / `cellWriter`):
  Modbus TCP, Modbus RTU (COM), MICROART, Малина — единый интерфейс чтения/записи/
  команд (`transport.go`).
- Парсер Modbus TCP (`modbus_client.go`) — аккуратная проверка transaction id,
  unit id, MBAP length, bytecount; защита от слайс-паники при усечённых кадрах;
  однократный реконнект при обрыве.
- Двухуровневая защита опасных параметров: `dangerKeys` + серверный флаг
  `allowDanger` (`catalog.go:1085`), защита служебной области `0x000..0x004`
  (`catalog.go:1091`), верификация чтением-обратно (`catalog.go:1138-1155`).
- Маскирование паролей в логах (`maskSecret`), журналирование значимых действий с
  параметрами.
- Детерминированная отладочная нумерация интерфейса с append-only порядком
  (`dbgindex.go` / `dbgorder.go`) — удобный и продуманный механизм.
- Тесты покрывают валидность каталога, порядок байт, связанные пары (`uacc10`,
  `u16_hi`, `cacc`, `pow2`, `i16_hi7`), маски старшего байта, синонимы режимов.
- Документация (README, CHANGELOG, DISCLAIMER) подробная и соответствует коду.

## Рекомендации по приоритету

1. Дефолт слушать `127.0.0.1` и/или требовать авторизацию + проверка Origin.
2. Глобальная сериализация операций записи.
3. Убрать мёртвый код (`mapSettingsTarget`/`validateMapTarget`/`address()`,
   `vis()`), согласовать дефолт протокола записи UI/конфиг.
4. Graceful shutdown (сигналы, корректное закрытие сервера/лога).
5. Ужесточить права `mapsettings.json` (`0600`) и вынести предупреждение о
   хранении пароля открытым текстом.

## Отработка — 2026-09-26

По указанию пользователя **п.1 и п.4 не выполнялись** (сетевой дефолт/авторизация
и хранение пароля открытым текстом оставлены как есть). Остальные пункты
отработаны.

### Критично / Высоко

- **п.2 (CSRF / Origin).** Добавлен `csrfGuard` (`server.go`), навешанный на весь
  mux: мутирующие методы (`POST` и т.п.) отклоняются кодом `403`, если заголовок
  `Origin` задан и его хост не совпадает с `Host` запроса. Отсутствие `Origin`
  (curl/CLI) не блокируется. Событие логируется.
- **п.3 (сериализация записи).** Добавлен общепроцессный `writeMu sync.Mutex`
  (`server.go`); взят в `apiApply`, `apiAction` и `apiTime` (POST) — операции
  записи больше не перекрываются между соединениями/вкладками.

### Средне

- **п.5 (мёртвый код).** Удалены `mapSettingsTarget`, `validateMapTarget`,
  `mapSettingsTarget.address()` и тест `TestMapSettingsValidateTarget`
  (`catalog.go`, `catalog_test.go`); убран неиспользуемый импорт `net`. В
  `web/app.js` удалена вложенная функция `vis()`.
- **п.6 (дефолт протокола записи).** `renderCfgUI` в `web/app.js` теперь
  подставляет `wrProto = 'malina'`, как и `defaultConfig().Write.Protocol`.
- **п.7 (graceful shutdown).** `main.go`: `signal.NotifyContext` (SIGINT/SIGTERM),
  `srv.Shutdown` с таймаутом, закрытие файла лога; ошибка `srv.Serve` больше не
  вызывает `log.Fatalf` в горутине, а передаётся через канал.
- **п.8 (коды ответов).** Ошибки подключения к МАП унифицированы как `502 Bad
  Gateway` (`apiSettings`, `apiParam`, `apiApply`, `apiAction`, `apiTime`).
  Некорректный ввод по-прежнему `400`.
- **п.9 (верификация записи).** `applyMapSettings` (`catalog.go`) больше не
  игнорирует ошибку обратного чтения: она попадает в результат как
  «верификация: ошибка обратного чтения…», а отсутствие ячейки — как «нет данных
  обратного чтения». Ключ результата — исходный `key` параметра (адрес `0x…`
  остаётся только как запасной вариант), для этого ведётся `addrKey`.
- **п.10 (`WriteTimeout`).** В `main.go` добавлен
  `WriteTimeout: readTimeout + 30*time.Second` (120 с) с учётом длинных операций.

### Низко

- Статика `/static/` отдаётся с `Cache-Control: no-store` (`noStore` в
  `server.go`), как index/API.
- `configPath()` (`config.go`): если каталог бинарника временный (`go run`),
  конфиг берётся из текущего каталога — старый файл рядом с временным бинарником
  больше не перекрывает рабочий; для обычной сборки поведение прежнее.
- `dangerKeys`: добавлен `isDangerKey()` (`catalog.go`), который распознаёт
  опасный параметр и после переименования дублирующегося ключа суффиксом `_%03x`
  (используется в `settingView` и `applyMapSettings`).
- `apiConfig` (`server.go`): `listen`/`user`/`pass` сохраняются из текущего
  состояния, если запрос их не прислал (UI их не отправляет), но непустые
  значения из запроса теперь позволяют изменить их через API.
