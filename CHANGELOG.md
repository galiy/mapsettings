## [Unreleased]

### Изменено
- Убраны все всплывающие при наведении подсказки (нативные `title`); описание
  параметра осталось только по клику на знак «?».
- Интерфейс разбит на экраны: главная (настройки программы, форма времени и
  кнопки разделов) и отдельный экран на каждый логический блок (одноимённые
  rw/ro-группы — на одной странице) плюс экран «Управляющие воздействия». В
  шапке раздела — «Перечитать», «Записать», «На главную» и переходы в другие
  разделы.
- Отладочный номер показывается как «№N» (было «#N»); нумерация сквозная между
  экранами и **детерминированная**: фиксированный список id → № строится на
  сервере (`dbgindex.go`), клиент получает его через `GET /api/dbgindex` и
  фиксирует в `localStorage`.
- Индекс отладочных номеров `.kilo/dbg-index.txt` (в `.gitignore`) с типами
  элементов; генерируется `make dbg-index` или `./mapsettings -dbgindex`.
- Порядок номеров зашит в `dbgindex_order.go` и **append-only**: новые элементы
  дописываются в конец (`make dbg-order`), уже выданные номера не сдвигаются.
- Серийный номер МАП: `_SerialNum0` (младший) и `_SerialNum1` (старший)
  объединены в один 16-битный параметр «Серийный номер МАП» (напр. 51510).
  Ячейки серийного номера (`_SerialNum0`, `_SerialNum2`, `_SerialNum3`) идут
  подряд и все помечены `danger`.
- Версии/идентификаторы показываются по смыслу: `_Device` — радио «Код
  устройства», `_VerPow` — поля «Версия платы» + «Гибрид», `_VerPlatNet` —
  «Версия» + «Тип» (low/Hi), `_VerPO` — «целая.дробная» (сейчас 4.3). Для этого
  добавлен общий механизм битовых полей (`fields`) и формат `ver`. Все они
  помечены `danger`.
- Тип МАП (Титанатор/Доминатор) определяется автоматически при первом чтении
  по ячейке `_DevOpt` (0x007) и подставляется в селектор «Модель». В
  `mapsettings.json` тип больше не хранится — только IP и порт; селектор в UI
  сохранён и может быть переопределён вручную.
- Отладочная нумерация стала стабильной: номер присваивается элементу один раз
  и хранится в `localStorage`; новые элементы получают следующий номер по
  порядку появления, существующие не перенумеруются.
- Каталог: восстановлены перечисления и описания 9 параметров, у которых список
  значений в документе переносился на следующую строку (`_POW`, `_UACC`,
  `_VerPO`, `_VerPlatNet`, `_SyncDiz_Plat`, `_LCD_TypeSin`, `_CulerSpead`,
  `_MPPT_toCh`, `_flagUnet2`). «Мощность устройства» (`_POW`) и «Рабочее
  напряжение МАП» (`_UACC`) теперь перечислимые: выбор из вариантов с
  подписями (кВт и В), а не ввод кода.

### Добавлено
- Отладочная сборка `make build-debug` (`-X main.debug=true`): все надписи и
  управляющие элементы нумеруются (№1, №2, …), номер всплывает сразу при
  наведении. В обычной сборке нумерация отключена.
- Защита опасных параметров: 60 ячеек (мощность/напряжение/токи АКБ,
  калибровки, аппаратная конфигурация) помечены `danger` и по умолчанию
  недоступны для редактирования. У таких параметров слева от имени — красная
  метка «▲ Опасно!». Редактирование включается кнопкой 🔒 в строке на время
  сессии; при общей записи заблокированные параметры не отправляются.
- В каждой строке колонки «Действия» — кнопки «Читать» (перечитать только этот
  параметр) и «Сохр.» (сохранить только этот параметр, если он изменён).
  «Сохр.» недоступна для нередактируемых и заблокированных параметров.
- API `GET /api/param?mode=&ip=&port=&key=` — чтение одного параметра.
- Серверная защита опасных параметров: без флага `allowDanger` в `POST /api/apply`
  запись помеченных `danger` ячеек отклоняется (флаг ставит UI после
  разблокировки).

### Исправлено
- Тип МАП больше не передаётся одиночными операциями до автоопределения; при
  смене IP/порта тип определяется заново.
- Битовые маски: недокументированные (не показанные чекбоксами) биты не
  затираются при записи; убран ложный признак «изменено» для значений вне
  списка вариантов.
- Параметр, у которого первое чтение дало ошибку, после успешного «Читать»
  снова получает редактор (был доступен только для чтения).
- `_RCON_img_H`: биты, пронумерованные в документе как 8…15, приведены к
  однобайтовой ячейке (0…7); уточнена формула `_VerPO`.
- Настройки: устранена гонка данных на значениях по умолчанию; адрес
  проверяется до сетевого обращения; `strconv`/мёртвый код/устаревшие
  комментарии убраны.

## [0.1.0] — 2026-09-26

Первая версия.

### Добавлено
- Веб-интерфейс: чтение, инспекция и запись ячеек МАП по Modbus TCP через
  `mapgateway`.
- Кнопки «Перечитать» / «Записать»; записываются только изменённые параметры.
- Два режима: Титанатор и Доминатор; режим, IP и порт сохраняются на клиенте
  (localStorage) и в локальном `mapsettings.json`.
- Служебное обрамление записи `03 (ComMAP_EEPromWR) → запись → 07
  (ComMAP_Call_load_EEProm)` с чтением-обратно.
- Разделы «Настройки» и «Управляющие воздействия и мониторинг» (команды и
  ro-параметры).
- Отдельная форма текущего времени МАП.
- Перечислимые параметры — радиогруппы, битовые маски — чекбоксы.
- Кнопка «?» с подсказкой из документации у каждого параметра и органа
  управления; русские имена и логические блоки.
- Каталог ячеек (227 параметров) `catalog.json`, генерируемый `catalog_gen.py`
  из `protocol_MAP_cells_2026_07_15.doc`.
